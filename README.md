# 转运站容量管理

服务按库区管理实际存量、车辆预约预占和待处置重量。预约有明确有效期，车辆入场后由实际净重替换预占重量，出库转运减少落地存量；每项变化均关联业务单据并记入台账。

## 容量模型

- 可用容量 = 上限 − 已落地存量 − 有效预占，任何时刻不为负。
- 不变量：已落地存量 + 有效预占 ≤ 上限，由服务在所有变更路径上共同维护。
- 待处置量：进场净重超出安全上限、未能落地的部分，单独记账等待处置分流，不计入可用容量扣减。
- 同一库区的预占、确认、调整、过期、取消、出库全部按库区串行落账，容量检查与变更在同一同步临界区内完成：并发请求只有一个先落账，其余看到最新容量后再判定，不会超发也不会重复释放。

## 接口（`src/capacity-service.js`）

- `reserve({id, expectedKg, expiresAt?, material?})` 预占；容量不足、物料类别不符、单据重复时拒绝。同一单据相同请求重复提交幂等返回。
- `arrive(id, actualKg)` 进场确认：实际净重高于预约时在安全范围内补占；超出安全上限的部分转入待处置，可用容量绝不为负。重复上报同一净重幂等；预约已过期时按无预占车辆处理。
- `adjust(id, {expectedKg?, expiresAt?})` 调整有效预占，上调受可用容量约束，下调立即释放。
- `cancel(id)` 取消并立即释放预占；重复取消幂等。
- `expireDue(now)` 过期任务：释放到期预占。状态守卫（仅 held 可流转）保证故障恢复后重跑不会重复释放，与车辆到场竞争时只有一个结果。
- `outbound({id, kg, source?})` 出库转运减少落地存量；`source: 'pending'` 核销待处置量。同一单据编号重放幂等，不重复扣减。
- `snapshot()` 班长核对视图：上限、已落地存量、有效预占、待处置量、可用容量与有效预占笔数。
- 所有拒绝均返回 `{status:'rejected', reason, message, snapshot}`，快照含当时容量全貌，可解释拒绝原因。

`src/capacity-store.js` 保存库区、预约、业务单据与变动台账，领域样例位于 `fixtures/zone.json`。项目要求 Node.js 20 或更高版本，运行 `npm test` 可检查顺序与并发流程。
